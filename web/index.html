Whetstone

Open-weight models are paid, per call, to make a Solidity function cheaper to run. Two questions decide whether the result means anything: does the rewritten function still do the same thing, and was the saving worth more than a one-word edit. Both are answered here, per run, with receipts on two chains.

The job

Each model is handed one pure Solidity function and asked to make it cost less gas. It is told the compiler settings and the exact inputs it will be measured on. It is not told where the function came from.

What the model receives

function f(uint256 x) external pure returns (uint256 r) {
    if (x == 0) revert ZeroHasNoBytes();
    r = (x > 0xffffffff...ffff ? 1 : 0) << 7;
    r |= ((x >> r) > 0xffffffffffffffff ? 1 : 0) << 6;
    r |= ((x >> r) > 0xffffffff ? 1 : 0) << 5;
    r |= ((x >> r) > 0xffff ? 1 : 0) << 4;
    return ((r >> 3) | ((x >> r) > 0xff ? 1 : 0)) + 1;
}

How many bytes are needed to hold x. It is a mutated copy of a well-known library function: the mutation makes the memorised answer wrong, so a model that recites from training data fails the equivalence check rather than scoring.

What one model returned

function f(uint256 x) external pure returns (uint256 r) {
    if (x == 0) revert ZeroHasNoBytes();
    uint256 lz;
    assembly { lz := clz(x) }
    r = (256 - lz + 7) / 8;
}

The whole shift chain replaced by one opcode. 206 gas per call cheaper, and proved to return the identical value for every one of the 2256 possible inputs.

Question 1 — does it still do the same thing?

A patch that is faster and wrong is worthless, so nothing is scored until a symbolic prover has compared the two contracts. Every row below carries how strong that check was:

Proved for every input. A solver explored the whole input space and found no difference in the returned value, in whether the call reverts, or in the revert data. This is not testing — no input was sampled, the claim is universal. FORMAL_NO_EXPLICIT_INPUT_BOUND
Fuzzed, not proved. The prover did not finish, so the patch was compared against the original over 20 000 pseudo-random inputs with a pinned seed. Evidence, not a guarantee. FUZZED
Undecided. The solver ran out of memory or time. ⚠️ Not a pass — an unfinished search is not evidence of anything. UNKNOWN
No patch. The model never returned something that compiled and passed the gates. The call was still paid for, so the attempt is recorded with its cost.

Question 2 — was the saving worth anything?

Wrapping the last line in unchecked removes an overflow check the compiler cannot prove unreachable. That single word saves 69 gas per call and requires understanding nothing about what the function does. It is the line every result is read against — a patch below it beat nothing but the compiler's caution.

Check any row without trusting this page

Each run writes a full receipt to Hedera Consensus Service and a pointer to it on Base Sepolia, which is what this subgraph indexes. Content hash is the sha256 of the HCS message as recorded on Base Sepolia. Open the receipt, hash it yourself, and compare — if they differ, one of the two chains is lying and you can prove which. Run ids link to the Base Sepolia transaction that wrote the pointer.

Worst single input is the largest amount a patch made any one input cost more. A patch can be cheaper on average and worse at a boundary, so it is reported next to the saving and never on its own.

What these numbers do not say

  • This is not a ranking of models. One function and a handful of runs. Ties are the normal outcome here and are reported as ties.
  • Percentage of baseline is measured against a 2024 implementation. Patches that beat it mostly reach for clz, an opcode the baseline predates, so the figure says as much about EVM versions as about models. The absolute gas column and the floor comparison do not involve the baseline and are unaffected.
  • A guarantee label is not a proof of usefulness. It says how thoroughly the patch was checked for equivalence, nothing about whether the saving matters downstream.
  • The floor is 69 gas per call for this task, established by proving the one-word edit equivalent to the task. It is a property of this function, not a constant.
